# 통합형 방송부 사이트

## Why

삼호중앙초 방송부는 지금 "방송부 대본 도우미"로 금요방송 대본을 AI와 함께 만들고 일정 캘린더를 씁니다. 하지만 사이트가 '대본 목록' 중심이라 부원이 들어와도 이번 주에 자기가 할 일, 새 소식, 선생님 의견을 한곳에서 볼 수 없고, 공지·메모는 사이트 밖(말·종이·메신저)에서 오갑니다. 담당 교사가 원하는 것은 **부원들이 매주 들어와 일정·공지·메모·대본을 한곳에서 해결하는 방송부 전용 사이트**(비전 실현)입니다. 동시에 부원 수가 늘면 생기는 AI 무료 한도 소진과 같은 주제 반복 문제를 미리 막아야 합니다.

## Capabilities

- **CAP-1 메뉴 개편**
  - **intent:** 부원이 홈·대본·일정·게시판·알림을 한 메뉴에서 오가며 모든 기능을 찾을 수 있다.
  - **success:** 휴대폰(360px)과 컴퓨터 화면 모두에서 메뉴로 다섯 곳에 각각 한 번의 누름으로 이동하고, 기존 주소(`?id=`, `?new`, `?calendar`, `?help`, `?accounts`)로 들어와도 같은 화면이 열린다.
- **CAP-2 통합 첫 화면**
  - **intent:** 로그인한 부원이 첫 화면에서 이번 주 방송, 내 할 일, 다가오는 일정, 새 공지를 한눈에 보고 바로 해당 화면으로 간다. 교사는 검토를 기다리는 대본도 본다.
  - **success:** 학생 계정으로 로그인하면 `/`에 네 묶음(이번 주 방송·내 할 일·다가오는 일정·새 공지)이 보이고 각 항목을 누르면 해당 대본·일정·공지가 열린다. 교사 계정에는 '검토 기다리는 대본' 묶음이 추가된다.
- **CAP-3 공지·메모 게시판**
  - **intent:** 교사는 공지를 올려 맨 위에 고정하고 누가 읽었는지 확인하며, 부원은 누구나 메모를 올려 방송부 안에서 소식을 나눈다.
  - **success:** 학생은 공지를 쓸 수 없고 메모는 쓸 수 있으며 자기 메모만 고치거나 지울 수 있다. 교사는 모든 글을 지울 수 있고, 공지마다 읽은 부원·안 읽은 부원 명단을 본다. 학생이 공지를 열면 읽음으로 기록된다.
- **CAP-4 선생님 검토 댓글**
  - **intent:** 교사가 대본의 구성(인사말·행사·사자성어·계기교육·마무리)별로 고칠 점을 댓글로 남기고, 학생이 고친 뒤 '반영함'으로 표시한다.
  - **success:** 교사가 '행사' 구성에 댓글을 달면 학생 편집 화면의 해당 탭에 댓글과 개수가 보이고, 학생이 '반영함'을 누르면 교사 화면에 반영 완료로 바뀐다. 완료된 대본에도 댓글 기록이 남는다.
- **CAP-5 알림 모아보기**
  - **intent:** 부원이 자기와 관련된 새 소식(새 공지, 내 대본의 검토 댓글·완료 처리, 나를 넣은 일정)을, 교사는 검토 요청을 한곳에서 안 읽음 표시와 함께 본다.
  - **success:** 교사가 공지를 올리면 모든 학생의 메뉴 알림 배지 숫자가 1 오르고, 알림을 누르면 공지가 열리며 숫자가 줄어든다. 학생이 검토 요청을 누르면 교사 알림에 해당 대본이 나타난다.
- **CAP-6 낭독 연습 모드**
  - **intent:** 아나운서가 대본을 큰 글씨로 구성별로 넘기며 소리 내어 연습하고, 걸린 시간을 예상 시간과 비교한다.
  - **success:** 대본에서 '연습하기'를 누르면 큰 글씨 연습 화면이 열리고, 타이머 시작·멈춤·구성별 넘기기가 되며, 끝나면 구성별 실제 시간과 예상 낭독 시간이 나란히 보인다. 2인 진행 대본에서는 '나는 ○○' 선택 시 내 대사만 강조된다.
- **CAP-7 사자성어·계기교육 중복 방지**
  - **intent:** 같은 학년도에 이미 방송한 사자성어·계기교육 주제가 다시 쓰이지 않게 한다.
  - **success:** 이번 학년도(3월 1일~이듬해 2월 말) 다른 대본에 쓴 사자성어는 AI가 고르지 않고, 주제 고르는 화면에서 이미 쓴 주제에 '이미 씀(방송일)' 표시가 붙는다. 학생이 직접 같은 주제를 고르는 것은 막지 않고 알려만 준다.
- **CAP-8 AI 사용량 제한**
  - **intent:** 학생 한 명이 하루에 AI를 쓸 수 있는 횟수를 정해 무료 한도와 장난 사용을 막는다.
  - **success:** 학생은 하루(한국 시간 자정 기준) 30번까지 AI 요청이 되고 31번째에는 쉬운 말 안내와 함께 거절된다. 화면에 남은 횟수가 보인다. 교사는 제한이 없다.

## Constraints

- 기존 기술 그대로: Cloudflare Workers + D1 + `public/` 바닐라 JS(빌드 도구 없음) + Gemini. 새 프레임워크·번들러·외부 서비스 추가 금지 (무료 한도 안에서 운영).
- 운영 규칙: 스토리마다 브랜치 → PR → 자동 검사 → 교사 Merge → Actions 배포 승인. main 직접 push·`wrangler deploy` 금지.
- 데이터베이스 변경은 `migrations/000N_*.sql`과 `schema.sql`에 함께 넣고, PR 설명과 스토리에 "배포 승인 전 관리자가 직접 실행"을 적는다. 기존 표·열은 지우거나 이름을 바꾸지 않는다(추가만).
- 공개 저장소: 비밀값(`GEMINI_API_KEY`, `TEACHER_PASSWORD`, `SESSION_SECRET`, `PLAN_SHEET_ID`)은 코드·문서에 값을 쓰지 않는다. 주간계획 시트 주소는 학생 화면에 보이지 않는다.
- 디자인 체계 유지: 'ON AIR' 빨강 `#CC3138` 단일 강조색, Pretendard 본문 + Jua 제목, Phosphor 아이콘, 이모지 없음, 다크 모드 지원 (`ux-design.md`).
- 휴대폰(폭 360px)·태블릿·컴퓨터 모두에서 가로 스크롤 없이 쓸 수 있어야 한다.
- 사용자는 초등학생: 화면 글은 쉬운 존댓말, 오류는 무엇을 하면 되는지 알려 준다.
- 권한은 서버에서 확인한다 (화면에서 버튼을 숨기는 것만으로는 안 됨). 교사만: 공지 작성, 검토 댓글 작성, 대본 '완료', 대본 삭제, 계정 관리, 남의 메모 삭제.
- 교사 로그인에는 계정 id(uid)가 없다: 교사 대상 기능(알림 등)은 '교사 공용'으로 처리한다 (`architecture.md`).
- 각 스토리는 사용법 화면(`?help`)에 해당 기능 설명을 함께 넣는다.

## Non-goals

- 로그인 시도 횟수 제한 (이번 범위 아님 — 추후 별도 작업).
- 푸시 알림·메일·문자 보내기 (알림은 사이트 안에서만).
- 메모 댓글·좋아요, 채팅·쪽지.
- 연습 녹음·녹음 파일 저장, 연습 기록 저장.
- 파일·사진 올리기 (게시판은 글만).
- 학생 계정 직접 가입 (계정은 계속 교사가 만든다), 학부모·다른 학교용 기능.

## Success signal

- 학생 한 명이 휴대폰으로 로그인해 첫 화면에서 새 공지를 읽고(교사 화면에 읽음 표시), 이번 주 대본의 검토 댓글을 보고 고쳐 '반영함'을 누르고, 연습 모드로 한 번 읽어 시간을 확인하는 흐름을 다른 화면을 헤매지 않고 마친다.
- 같은 학년도에 같은 사자성어가 두 번 방송되지 않고, 학생 한 명의 AI 요청이 하루 30번을 넘지 않는다.

## Assumptions

- '내 대본' = 만든 사람이 나이거나 아나운서 칸에 내 이름이 있는 대본. 기존 데이터가 이름 글자로 저장되어 있기 때문이며, 동명이인은 계정 이름에 학년 등을 붙여 구분한다.
- 검토 댓글은 교사만 쓰고, 학생은 '반영함' 표시만 한다(답글 없음).
- 공지 읽음 확인은 학생 계정만 대상이다(교사 로그인은 개인 id가 없음).
- 알림·읽음 기록은 일정 기간(90일)이 지나면 지워도 된다.

## Open Questions

- 학년이 바뀔 때(3월) 지난 공지·메모를 보관할지, 지울지, 그대로 둘지? (지금 설계는 그대로 두고 목록에서 최신순으로만 보여 줌)
- AI 하루 30번 한도를 교사가 화면에서 바꾸게 할지, 설정 파일(`wrangler.jsonc`의 `vars`)로만 바꿀지? (지금 설계는 `vars`의 `AI_DAILY_LIMIT`, 기본 30)
