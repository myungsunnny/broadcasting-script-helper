# UX 설계: 메뉴·첫 화면·화면 구성

SPEC.md의 CAP-1~8을 화면으로 옮긴 기준. 기존 디자인 토큰(`public/style.css`의 `:root`)과 모양 규칙(카드 18px, 입력칸 12px, 버튼·칩·탭 알약)을 그대로 쓴다. 새 색을 만들지 않는다.

## 1. 디자인 원칙

1. **한 화면에 할 일 하나가 크게.** 첫 화면의 '이번 주 방송' 버튼처럼 가장 중요한 행동은 큰 빨강 버튼 하나. 나머지는 카드 안 목록.
2. **강조색은 빨강 하나.** 안 읽음 배지, 현재 메뉴, 주요 버튼에만. 상태 구분은 기존 `--ok / --warn / --info` 계열 배지로.
3. **초등학생 말투.** 버튼은 동사로 짧게("공지 쓰기", "반영했어요", "연습하기"). 빈 화면에는 다음에 할 일을 알려 주는 한 줄.
4. **아이콘 + 글자.** 아이콘만 있는 버튼은 좁은 화면의 상단바뿐이며 `aria-label` 필수.
5. **다크 모드·키보드.** 새 요소도 토큰 색만 사용. 모든 버튼은 Tab으로 닿고 포커스 테두리가 보인다.

## 2. 메뉴 (CAP-1)

### 메뉴 항목

| 순서 | 이름 | 아이콘(Phosphor) | 주소 | 비고 |
|---|---|---|---|---|
| 1 | 홈 | `house` | `/` | 통합 첫 화면 |
| 2 | 대본 | `microphone-stage` | `/?scripts` | 기존 대본 목록 (검색·상태 거르기·다른 날 대본) |
| 3 | 일정 | `calendar-dots` | `/?calendar` | 기존 캘린더 그대로 |
| 4 | 게시판 | `push-pin` | `/?board` | 공지 + 메모 |
| 5 | 알림 | `bell` | `/?inbox` | 안 읽은 수 배지 |

계정 관련(내 이름, 비밀번호 바꾸기, 학생 계정 관리[교사], 사용법, 로그아웃)은 메뉴가 아니라 상단바 오른쪽 **'내 이름' 버튼을 누르면 열리는 작은 목록**으로 옮긴다. 사용법은 로그인 전에도 지금처럼 로그인 화면 링크로 연다.

### 배치

```
넓은 화면 (720px 이상)
┌──────────────────────────────────────────────────────────────┐
│ [●] 삼호중앙초 방송부   홈  대본  일정  게시판  알림(3)   [김방송 ▾] │
└──────────────────────────────────────────────────────────────┘
  - 현재 메뉴: 빨강 글자 + 아래 2px 빨강 밑줄
  - 상단바 고정(sticky)

좁은 화면 (720px 미만)
┌──────────────────────────┐
│ [●] 방송부        [김방송 ▾]│  ← 상단바: 로고 + 내 이름만
│                          │
│        (화면 내용)         │
│                          │
├──────────────────────────┤
│ 홈  대본  일정  게시판  알림 │  ← 하단 탭 막대 고정, 아이콘 위 / 글자 아래
└──────────────────────────┘
  - 각 칸 최소 48×48px, 아이폰 하단 안전 영역(env(safe-area-inset-bottom)) 확보
  - 현재 칸: ph-fill 아이콘 + 빨강
  - 알림 배지: 빨강 원 + 흰 숫자, 10 이상은 "9+"
```

- 브랜드 이름은 "방송부 대본 도우미" → **"방송부"** (넓은 화면은 "삼호중앙초 방송부"). `<title>`은 "방송부 · 학교이름".
- 대본 편집(`?id=`, `?new`)·방송용 보기·연습 모드에서는 '대본' 메뉴가 현재 메뉴로 표시된다. **연습 모드는 메뉴를 숨긴 전체 화면**.
- 임시 비밀번호 학생(비밀번호를 바꿔야 함)에게는 메뉴를 보이지 않는다.

## 3. 통합 첫 화면 (CAP-2)

### 학생

```
┌─────────────────────────────────────────┐
│ 안녕하세요, 김방송님                       │  ← Jua 제목, 오늘 날짜 작게
│ 11월 2일 월요일                            │
├─────────────────────────────────────────┤
│ [마이크] 이번 주 대본 이어서 만들기   →      │  ← 기존 hero 버튼 그대로
│ 11/6(금) 방송 · 지금 상태: 검토요청        │
├─────────────────────────────────────────┤
│ 내 할 일                         (2)     │
│  • 11/6 대본에 선생님 의견 2개 → 고치러 가기 │
│  • 내일 15:00 아나운서 연습 (함께: 이아나)   │
├────────────────────┬────────────────────┤
│ 새 공지          더보기│ 다가오는 일정   캘린더│
│ [고정] 11월 방송 순서… │ 11/4 연습 15:00     │
│  새  금요일 리허설 …   │ 11/6 방송 [대본]    │
└────────────────────┴────────────────────┘
  넓은 화면: 위 두 카드는 한 줄, 아래 두 카드는 2열
  좁은 화면: 모두 한 열. 순서 = 인사 → 이번 주 방송 → 내 할 일 → 새 공지 → 다가오는 일정
```

**내 할 일** (위에서부터, 최대 5개, 없으면 "오늘은 할 일이 없어요. 대본 목록을 둘러볼까요?")

1. 내 대본 중 '반영함' 안 된 검토 댓글이 있는 대본 → 그 대본 편집 화면, 댓글 있는 첫 탭
2. 내 대본 중 상태 '작성중'이고 방송일이 오늘~7일 안 → 편집 화면
3. 내가 '함께하는 부원'인 일정 중 오늘·내일 → 캘린더 그날
4. 안 읽은 고정 공지 → 공지 상세

**새 공지**: 고정 공지 먼저, 그다음 최근 공지 3개. 안 읽은 공지 앞에 빨강 '새' 칩.
**다가오는 일정**: 오늘부터 5개(기존 `upcoming`을 3 → 5). 대본이 있는 방송일은 '대본' 칩.

### 교사

학생 화면에서 '내 할 일' 대신 **검토 기다리는 대본** 카드(상태 '검토요청' 대본 목록, 방송일 빠른 순)를 맨 위에 두고, 공지 카드에는 "공지 쓰기" 버튼과 공지마다 "읽음 12/15" 표시를 붙인다. 이번 주 방송 버튼은 그대로.

### 처음 온 학생

기존 '처음 왔나요? 사용법 보기' 안내 띠를 첫 화면 맨 위로 옮긴다(동작 동일).

## 4. 게시판 (CAP-3)

```
게시판                                  [공지 쓰기](교사) [메모 쓰기]
[전체] [공지] [메모]                     ← 알약 탭, 기본 '전체'
──────────────────────────────────────
[핀] 공지  11월 방송 순서 안내   선생님 · 11/1   새   ← 고정 공지(최대 3개) 항상 맨 위
     공지  리허설 시간 변경       선생님 · 10/30
     메모  음향 케이블 정리함 위치  이아나 · 10/29
──────────────────────────────────────
더 보기 (20개씩)
```

- **글 쓰기/고치기**: 대화상자(`<dialog>`). 칸 = 제목(최대 60자), 내용(최대 2000자, 줄바꿈 유지). 교사가 공지를 쓸 때만 '맨 위에 고정' 체크.
- **글 보기**: 목록에서 누르면 펼쳐지는 카드(새 화면 아님). 주소는 `/?board&post=<id>`로 바뀌어 링크 공유 가능.
- **읽음 기록**: 학생이 공지를 펼치면 읽음으로 기록. '새' 칩이 사라진다.
- **교사의 읽음 확인**: 공지 카드 아래 "읽음 12 / 15" 버튼 → 펼치면 '읽은 부원'과 '아직 안 읽은 부원' 이름 칩 두 줄.
- **권한 표시**: 고치기·지우기 버튼은 쓸 수 있는 사람에게만 보인다(서버도 확인). 지우기 전 확인창.
- 빈 화면: "아직 글이 없어요. 방송부에 알리고 싶은 것을 메모로 남겨 보세요."

## 5. 대본 편집 화면 추가 (CAP-4, CAP-6, CAP-7, CAP-8)

### 검토 댓글 (CAP-4)

- 4단계(고치기)의 구성 탭 이름 옆에 반영 안 된 댓글 수 배지(`--warn` 계열, 빨강 아님 — 빨강은 알림 배지 전용).
- 탭 내용 위에 댓글 카드: `선생님 · 11/3 15:20` + 내용 + [반영했어요] 버튼. 반영한 댓글은 흐리게 접혀 "반영함 · 김방송 11/3" 표시.
- 교사에게는 각 탭 아래에 "의견 남기기" 입력칸(한 줄 → 누르면 늘어남)과 [남기기] 버튼. 교사는 자기 댓글을 지울 수 있다.
- '검토요청' 상태에서 교사가 댓글을 남기면 상태는 그대로 두고 학생이 고친 뒤 다시 검토 요청한다(기존 흐름 유지).

### 연습하기 버튼 (CAP-6)

대본 편집 화면 상단 도구줄과 방송용 보기에 [연습하기](`timer` 아이콘). 대본에 글이 하나도 없으면 비활성 + "대본을 먼저 써요".

### 이미 쓴 주제 표시 (CAP-7)

2단계(행사·주제 고르기)의 계기교육 주제 목록과 사자성어 주제 칸 아래:
- 이미 쓴 주제 칩: 회색 + 취소선 없음 + 작은 글씨 "이미 씀 · 9/12". 고를 수는 있다.
- 직접 입력한 주제가 이미 쓴 것이면 칸 아래 `--warn` 안내: "9월 12일 방송에서 이미 썼어요. 그래도 쓸까요?"

### AI 남은 횟수 (CAP-8)

- AI 버튼이 있는 곳(3단계 초안 만들기, 4단계 탭별 다시 쓰기) 옆에 작은 글씨 "오늘 AI 27번 남음". 5번 이하이면 `--warn` 색.
- 다 쓰면 AI 버튼 비활성 + "오늘 AI를 다 썼어요. 내일 다시 쓸 수 있어요. 급하면 선생님께 말씀드려요." 직접 쓰기는 계속 가능.
- 전체 초안 만들기는 5번을 쓰므로 남은 횟수가 5 미만이면 버튼에 "남은 횟수가 부족해요" 안내, 구성별 쓰기는 가능.
- 교사에게는 표시하지 않는다.

## 6. 낭독 연습 모드 (CAP-6)

주소 `/?practice=<대본id>`. 메뉴 없는 전체 화면, 어두운 배경 고정(방송실 조명 대비) — 단, 다크/라이트 토큰 중 다크 값을 사용.

```
┌──────────────────────────────────────────┐
│ [x 끝내기]   ② 다음 주 학교 행사 (2/5)  [A- A+] │
│                                          │
│   김방송: 이어서 다음 주 학교 행사를          │  ← 큰 글씨(기본 32px, 20~56px)
│   알려 드립니다. 월요일에는 …               │     내 대사는 진하게, 남의 대사는 흐리게
│                                          │
│ ──────────────────────────────────────── │
│        00:42   /  예상 0:50               │  ← 타이머(Jua, 크게)
│   [◀ 이전]   [▶ 시작 / ❚❚ 멈춤]   [다음 ▶]   │  ← 하단 큰 버튼 3개, 최소 56px
└──────────────────────────────────────────┘
```

- 시작 전: 2인 진행 대본이면 "나는 누구예요?" [아나운서1] [아나운서2] [둘 다] 선택.
- 타이머는 구성마다 따로 잰다. 다음으로 넘기면 그 구성 시간이 기록된다.
- 키보드: 스페이스 = 시작/멈춤, → = 다음, ← = 이전, Esc = 끝내기.
- 화면 꺼짐 방지(Wake Lock, 지원하는 브라우저만).
- 끝 화면: 구성별 표(구성 | 실제 | 예상 | 차이), 전체 합계. 예상보다 20% 이상 빠르면 "조금 천천히", 20% 이상 느리면 "조금 빠르게" 안내. [다시 연습] [대본으로 돌아가기]. 저장하지 않는다.
- 예상 시간은 기존 `readTimeText` 계산 규칙과 같은 글자 수 기준을 쓴다.

## 7. 알림 (CAP-5)

```
알림                                   [모두 읽음]
──────────────────────────────────────
●  [핀] 새 공지: 11월 방송 순서 안내           방금
●  [말풍선] 11/6 대본에 선생님 의견이 2개 달렸어요  1시간 전
   [체크] 10/30 대본이 완료되었어요             어제
   [달력] 이아나님이 11/4 연습에 나를 넣었어요     어제
──────────────────────────────────────
  ● = 안 읽음(빨강 점), 안 읽은 줄은 배경 --accent-soft
```

- 누르면 해당 화면으로 가고 그 알림은 읽음 처리.
- 최근 90일, 최대 50개. 빈 화면: "새 소식이 없어요."
- 메뉴 배지 숫자는 화면을 옮길 때마다(라우팅 시) 새로 받아 온다. 실시간 갱신·푸시는 없다.

| 알림 종류 | 받는 사람 | 생기는 때 | 누르면 |
|---|---|---|---|
| 새 공지 | 사용 중인 모든 학생 | 교사가 공지를 올릴 때 | 공지 펼침 |
| 검토 댓글 | 그 대본의 '내 대본' 학생들 | 교사가 댓글을 남길 때 | 대본 해당 탭 |
| 대본 완료 | 그 대본의 '내 대본' 학생들 | 교사가 상태를 '완료'로 바꿀 때 | 대본 |
| 일정에 넣음 | 새로 '함께하는 부원'이 된 학생 (본인이 넣은 경우 제외) | 일정 만들기·고치기 | 캘린더 그날 |
| 검토 요청 | 교사(공용) | 학생이 '검토 요청'을 누를 때 | 대본 |

## 8. 사용법 화면

각 스토리가 자기 기능의 절을 `helpView`에 더한다. 차례(`help-toc`)에 메뉴 순서(홈·대본·일정·게시판·알림·연습)대로 항목을 둔다.

## 9. 반응형·접근성 점검표 (모든 스토리 공통)

- 360px, 768px, 1280px 폭에서 가로 스크롤 없음.
- 누를 수 있는 것 최소 44×44px (연습 모드 하단 버튼 56px).
- 라이트/다크 모두 글자 대비 4.5:1 이상 (기존 토큰 사용 시 충족).
- 새 화면도 `<section id="…View" class="hidden">` + `showOnly()` 패턴.
- 아이콘 전용 버튼 `aria-label`, 배지 숫자는 `aria-label="안 읽은 알림 3개"`.
